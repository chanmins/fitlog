# 기록 검색 — 설계 + 구현 명세

작성 2026-09-02 · 대상 빌드 v76 → v77

## 0. 한 문장

**검색은 '세션 찾기' 가 아니라 '운동 하나의 이력으로 들어가는 문' 입니다.**

---

## 1. 먼저 정리한 것: 검색이 답해야 하는 질문은 두 종류뿐

운동 기록 앱에 던지는 질문을 다 모아 보면 축이 둘입니다.

| 축 | 질문 | 지금 상태 |
|---|---|---|
| **날짜 축** | "3월 12일에 뭐 했지" | **이미 완벽합니다** — 히스토리 달력 |
| **운동 축** | "벤치, 내가 어떻게 해왔지" | **문이 없습니다** |

날짜 축은 달력이 이미 해결했습니다. 그러니 검색을 만들면서 "매칭된 날짜 목록"
을 뱉으면 달력이 하는 일을 더 나쁘게 다시 하는 겁니다.

그리고 운동 축을 파 보면 **목적지 화면은 이미 절반쯤 만들어져 있습니다.**
`renderExerciseInfoSheet()` 안에 `renderExerciseTrend()` 가 붙어 있어서 최근
10회 최고 중량 그래프가 이미 그려집니다. 문제는 **거기 갈 방법이 두 개뿐**
이라는 것입니다.

- 그 운동이 **오늘 기록에 담겨 있을 때** 카드의 ⓘ
- **운동을 고르는 중일 때** 피커 안의 ⓘ

즉 "6개월 전에 하던 운동" 의 이력을 보려면, 그 운동을 오늘 기록에 **일단
담아야** 합니다. 담고 → 보고 → 다시 지워야 합니다.

> **그래서 이 기능의 정체는 '검색' 이라기보다 그 문을 다는 일입니다.**
> 검색창은 그 문의 손잡이고요.

## 2. 어디서 검색하나 — 진입점

### 결론: 히스토리 탭 상단 바의 돋보기 → 전체 화면

```
┌──────────────────────────────┐
│  히스토리                  🔍 │   ← 여기
└──────────────────────────────┘
```

`renderHistory()` 의 상단 바가 지금 이렇습니다:

```html
<header class="topbar"><div class="topbar-title">히스토리</div></header>
```

오른쪽이 **비어 있습니다.** 아이콘 하나 놓을 자리가 이미 있고, 히스토리 탭은
"지난 기록을 보러 오는 곳" 이라 검색이 있어야 할 곳으로도 가장 자연스럽습니다.

### 다른 안을 버린 이유

| 안 | 왜 버렸나 |
|---|---|
| 히스토리 상단에 **상시 검색 바** | 이 탭의 주인공은 달력입니다. 달력 위에 바를 얹으면 매번 스크롤 한 칸을 뺏기는데, 검색은 매일 쓰는 기능이 아닙니다 |
| **5번째 탭** | 하단 탭 4개가 지금 딱 맞습니다. 검색은 탭 하나를 영구히 차지할 만큼 자주 쓰지 않습니다 |
| 홈에서 **아래로 당기기**(Spotlight 식) | 발견이 불가능합니다. 게다가 홈에는 이미 pull-to-refresh 제스처가 잡혀 있습니다 |
| 시트(`.sheet-panel`) | 키보드가 올라오면 패널이 반쪽이 됩니다. 검색은 시작하는 순간 화면을 다 써야 하는 작업입니다 |

전체 화면은 `.detail-screen` 을 씁니다 — `renderDaySummary`·`renderRoutineEditor`
가 쓰는 그 패턴이라 `syncOverlayScroll()` 이 이미 스크롤·바디 클래스를
관리해 줍니다.

## 3. 검색 화면 UX

### 3.1 아무것도 안 쳤을 때 — 여기가 제일 중요합니다

검색창을 열었는데 빈 화면이면 사람은 **뭘 쳐야 할지 모릅니다.** 그리고 사실
대부분의 경우 치고 싶지도 않습니다. 사람은 같은 운동을 반복하니까요.

```
┌──────────────────────────────┐
│ ←  [🔍 운동 이름으로 찾기   ] │
├──────────────────────────────┤
│  자주 한 운동                 │
│                               │
│  벤치프레스           42회 ›  │
│  스쿼트               38회 ›  │
│  랫풀다운             31회 ›  │
│  데드리프트           27회 ›  │
│  덤벨 숄더프레스      24회 ›  │
│  바벨로우             22회 ›  │
│  레그프레스           19회 ›  │
│  인클라인 프레스      17회 ›  │
├──────────────────────────────┤
│  최근 기록한 운동             │
│  케이블 크로스오버   3일 전 › │
│  페이스풀            3일 전 › │
└──────────────────────────────┘
```

**이 빈 상태가 검색의 90% 를 흡수합니다.** 타이핑 없이 탭 한 번. 검색창은
나머지 10%(가끔 하는 운동, 오래전에 하던 운동)를 위한 것이고요.

'자주' 는 전체 기록의 **세션 수** 기준입니다 — 세트 수로 하면 고반복 운동이
위로 올라오고, 볼륨으로 하면 하체가 전부 차지합니다. "몇 번 했나" 가 "얼마나
자주 찾을까" 에 가장 가깝습니다.

### 3.2 입력 중 — 결과를 두 묶음으로

```
┌──────────────────────────────┐
│ ←  [🔍 벤치                ✕] │
├──────────────────────────────┤
│  내가 기록한 운동             │
│                               │
│  벤치프레스                   │
│  42회 · 최고 100kg×5 · 3일 전›│
│                               │
│  인클라인 벤치프레스          │
│  17회 · 최고 70kg×8 · 12일 전›│
├──────────────────────────────┤
│  운동 라이브러리 (3)      펼침▾│
└──────────────────────────────┘
```

**이 2분할이 핵심입니다.** "벤치" 를 치면 라이브러리에는 벤치프레스·인클라인·
디클라인·클로즈그립·덤벨벤치… 가 다 걸리는데, 내가 실제로 하는 건 보통
둘입니다. **해 본 것과 안 해 본 것을 섞으면 매번 눈으로 골라내야 합니다.**

- **내가 기록한 운동** — 위에, 펼친 채로. 각 줄에 `횟수 · 최고 기록 · 마지막
  날짜`. 이 한 줄이 사실 대부분의 질문에 이미 답합니다.
- **운동 라이브러리** — 아래에, 접은 채로. 아직 안 해 본 것들. 눌러도 이력은
  없으니 기존 정보 시트(동작·팁)로 보냅니다.

### 3.3 한글 초성 검색 — 이게 빠지면 반쪽입니다

`ㅂㅊ` → 벤치프레스 · `ㅅㅋㅌ` → 스쿼트 · `ㄷㄷㄹㅍㅌ` → 데드리프트

한국어 앱에서 이건 있고 없고의 차이가 아니라 **쓸 만하냐 아니냐의 차이**
입니다. 운동 이름이 길어서(인클라인 덤벨 벤치프레스) 온전히 치는 사람이
없습니다.

라이브러리는 51KB짜리 상수라 앱 뜰 때 초성 인덱스를 한 번 만들어 두면
됩니다. 유니코드 한글 음절은 규칙적이라 변환이 10줄입니다.

```js
const CHO = ['ㄱ','ㄲ','ㄴ','ㄷ','ㄸ','ㄹ','ㅁ','ㅂ','ㅃ','ㅅ','ㅆ','ㅇ','ㅈ','ㅉ','ㅊ','ㅋ','ㅌ','ㅍ','ㅎ'];
function chosung(str) {
  let out = '';
  for (const ch of str) {
    const c = ch.charCodeAt(0) - 0xAC00;
    out += (c >= 0 && c <= 11171) ? CHO[Math.floor(c / 588)] : ch;
  }
  return out;
}
```

매칭 순서: **① 이름 앞부분 일치 → ② 이름 포함 → ③ 영문명 포함 → ④ 초성
일치.** 이 순서를 지켜야 "벤치" 를 쳤을 때 `벤치프레스` 가 `클로즈그립 벤치`
보다 위에 옵니다.

### 3.4 자연어 질의는 하지 마세요

제가 먼저 꺼낸 얘기지만 접겠습니다. "데드리프트 100kg 처음 친 날" 같은 걸
파싱하려면 규칙 기반은 금방 깨지고("작년 여름", "요새", "제일 무겁게 들었을
때"), LLM 호출은 **오프라인이 안 되고**(이 앱의 핵심 특성입니다) 비용이
붙습니다.

그리고 4절의 이력 화면이 있으면 **그 질문의 답이 이미 화면에 목록으로
보입니다.** 파싱할 이유가 사라집니다.

대신 필터 칩 두 개로 90% 를 덮습니다 — 싸고, 오프라인이고, 예측 가능합니다.

```
[ 전체 ] [ 최근 3개월 ] [ 최고 기록만 ]
```

## 4. 목적지 — 운동 이력 화면 (이 기능의 본체)

검색 결과를 누르면 여기로 옵니다. **새 전체 화면**입니다.

```
┌──────────────────────────────┐
│ ←  벤치프레스        동작보기 │
├──────────────────────────────┤
│   42회      100kg×5     82t   │
│   기록      최고 기록   총 볼륨│
├──────────────────────────────┤
│  [3개월] [1년] [전체]         │
│      ╱╲    ╱                  │
│  ╱╲╱   ╲╱     ← 추세          │
├──────────────────────────────┤
│  기록                         │
│  8월 28일   100×5  95×8  95×7 │
│  8월 21일   PR 100×5  95×6    │
│  8월 14일    97.5×5  95×7     │
│  ...                          │
└──────────────────────────────┘
```

**아래쪽 날짜별 목록이 "작년 여름에 몇 kg 했더라" 의 실제 답입니다.** 그래프는
추세를 보여 주지만 정확한 숫자를 못 읽습니다. 목록은 읽힙니다.

그리고 이 목록의 날짜를 누르면 **그날 전체 기록**(`state.summaryDate`
오버레이)으로 넘어갑니다 — **운동 축에서 날짜 축으로 건너가는 다리**입니다.
"아, 그날 벤치를 100 쳤네. 그날 뭘 같이 했더라?" 가 한 탭입니다.

### 왜 기존 정보 시트를 확장하지 않고 새 화면인가

두 화면이 답하는 질문이 다릅니다.

- **정보 시트** = "이 운동을 **어떻게** 하나" (사진 3장, 근육맵, 팁) — 라이브러리 정보
- **이력 화면** = "내가 이걸 **어떻게 해왔나**" (기록, 추세, 날짜) — 내 데이터

한 시트에 다 넣으면 사진 3장 + 바디맵 + 그래프 + 42줄 목록 + 팁이 되어
스크롤이 지옥이 됩니다. 대신 서로를 링크합니다.

- 이력 화면 우상단 **`동작 보기`** → 기존 정보 시트
- 정보 시트의 추세 그래프 자리 → **`전체 기록 보기 →`** 버튼 추가

덤으로, **커스텀 운동도 이력 화면은 열립니다.** 지금 정보 시트는
`if (!libEx) return ''` 이라 사용자가 직접 추가한 운동은 아예 안 열립니다 —
이력 화면은 이름 기준이라 그 제약이 없습니다.

## 5. 구현 명세

### 5.1 운동 이름이 키입니다

`lastLog()`, `allPersonalBests()`, `renderExerciseTrend()` 가 전부 `ex.name`
으로 묶습니다. id 가 아닙니다. 검색도 **같은 기준을 따릅니다** — 여기서만
id 로 묶으면 같은 운동에 대해 화면마다 다른 숫자가 나옵니다(정보 시트 주석에
이미 같은 사고가 기록돼 있습니다).

부작용은 알고 갑니다: 운동 이름을 바꾸면 이력이 거기서 끊깁니다. 지금도
그렇고, 이번에 바꾸지 않습니다.

### 5.2 집계 캐시

`state.sessions` 는 이미 전부 메모리에 있습니다. 2년치라도 300세션 ×
5운동 × 5세트 = 7,500세트라 선형 스캔이 1ms 대입니다. **인덱스는 필요
없습니다.**

다만 **키를 칠 때마다 전체 스캔 + 집계**는 저사양 폰에서 렉으로 보입니다.
운동별 집계는 한 번만 만들고 캐시합니다.

```js
/* name → { name, part, count, lastDate, best:{kg,reps,date}, volume, days:[...] }
   sessions 가 바뀌면(기록 추가·삭제·동기화 수신) 버립니다. */
let _exIndex = null;
function exIndex() {
  if (_exIndex) return _exIndex;
  const map = new Map();
  for (const s of state.sessions) { /* … 한 번 훑기 … */ }
  _exIndex = [...map.values()].sort((a, b) => b.count - a.count);
  return _exIndex;
}
function invalidateExIndex() { _exIndex = null; }
```

`persist()`, `loadWorkspace()`, 클라우드 pull 이 끝나는 지점에서
`invalidateExIndex()` 를 부릅니다. **부르는 걸 빠뜨리면 방금 기록한 운동이
검색에 안 나옵니다** — 조용해서 알아채기 어려운 종류의 버그라, 세션 배열을
갈아 끼우는 곳을 전부 찾아 붙여야 합니다.

### 5.3 ⚠️ 입력 포커스 — 이 앱에서 가장 중요한 제약

`render()` 는 `#app` 을 innerHTML 로 통째로 갈아 끼웁니다. **타이핑 도중
`render()` 를 부르면 input 이 파괴되고 키보드가 내려갑니다.**

피커 검색이 이미 이 문제를 이렇게 우회했습니다 (`onInputEvt`):

```js
if (t.dataset.act === 'search-ex') {
  state.exerciseSearch = t.value;
  const list = document.querySelector('.pick-list');
  if (list && state.pickerPart) list.innerHTML = buildPickItems(state.pickerPart);
}
```

**정확히 같은 방식을 씁니다.** 결과 컨테이너 하나만 교체합니다.

```js
if (t.dataset.act === 'search-log') {
  state.logSearch = t.value;
  const box = document.querySelector('.search-results');
  if (box) box.innerHTML = buildSearchResults();
}
```

| 파일 | 변경 |
|---|---|
| `app.js` | state 에 `searchOpen`, `logSearch`, `searchFilter`, `exHistoryName` 추가 |

| | `renderSearchScreen()`, `renderExHistory()` |

| | `renderExerciseInfoSheet()` 에 `전체 기록 보기 →` |

| | `onInputEvt` 에 `search-log` 분기 |

| `styles.css` | 검색 화면·이력 화면 스타일. `.search-bar`·`.recent-row`·`.stats-card` 재사용 |
| `index.html`·`sw.js` | v77 |

**저장소·동기화·백업 변경 없음.** 전부 이미 있는 데이터를 읽기만 합니다 —
IndexedDB 버전도 그대로, `firestore.rules` 도 그대로입니다.

### 5.5 뒤로가기

전체 화면 두 개가 겹칠 수 있습니다(검색 → 이력 → 그날 기록). 하드웨어 뒤로
가기가 앱을 통째로 닫으면 안 됩니다. 지금 `state.summaryDate` 오버레이도
같은 문제를 안고 있으니, `popstate` 처리를 이번에 **한 곳에서** 정리합니다 —
열 때 `history.pushState`, `popstate` 에서 가장 위 화면만 닫기.

- [ ] "벤치" 검색 시 `벤치프레스` 가 `클로즈그립 벤치` 보다 위
- [ ] 타이핑 중 키보드가 내려가지 않는가 (5.3)
- [ ] 기록이 0건인 새 계정에서 빈 상태가 라이브러리로 안내되는가
- [ ] 커스텀 운동이 검색·이력 화면에 나오는가
- [ ] 방금 기록한 운동이 즉시 검색되는가 (5.2 캐시 무효화)
- [ ] 이력 화면 → 날짜 탭 → 그날 요약 → 뒤로 3번에 앱이 안 닫히는가
- [ ] 300세션 더미 데이터에서 키 입력 지연이 없는가
- [ ] 운동을 한 번도 안 한 라이브러리 항목을 눌렀을 때 정보 시트로 가는가
